# [CPS-009] A script takes arguments from the main search

**Status**: Open
**Priority**: High
**Component**: `src/CmdPal.Extension.Shortcuts/ShortcutsCommandsProvider.cs`, `src/CmdPal.Extension.Shortcuts/StartFileCommand.cs`, a new parameters page in `src/CmdPal.Extension.Shortcuts/`, `src/FoldersCatalog/`

**Summary**:
As a user of `~\shortcuts`, I want to pick a `.ps1`, `.bat` or `.cmd` script in the main search
and give it arguments there, so that a script like `px-proxy start` or `px-proxy stop` runs
without typing its path.

**Description**:
Keypirinha does this in one flow: type `px`, `px-proxy.bat` shows up, Tab locks the item in
and the input box takes arguments, Enter runs `px-proxy.bat stop` in the script's folder.
Scripts in `shortcuts` like `px-proxy` only make sense with a verb, so this is the gap that
matters most against Keypirinha.

Today `StartFileCommand` starts every file through the shell in its own folder, with no
arguments. For a `.ps1` that is the shell's default verb, which opens the script in an editor
instead of running it. The only way to pass arguments is Command Palette's built-in
*Run commands* (`>`), which needs the full path and does not start the script in its own
folder.

The `.bat` files in `shortcuts` are wrappers around `.ps1` scripts. The author moves them to
`.ps1`, with `.ps1` wrappers for scripts in other languages, so `.ps1` is the main case;
`.bat` and `.cmd` take arguments the same way.

This item is the follow-up named by the CPS-002 Scope Decision *Arguments for `.bat` later*.

**Scope Decisions**:
- **The SDK's parameters page, not Tab**: PowerToys 0.100 added parameter pages to Command
  Palette (`ParametersPage` with `StringParameterRun` in the toolkit; PowerToys PR #47826,
  issue #40948). Enter on a command with parameters opens the page in the search box; Tab to
  lock an item in, as in Keypirinha, is not offered by the SDK. The script's command opens a
  `ParametersPage` with one free-text field; its text becomes the arguments, and Enter runs
  the script. Two Enters instead of Tab plus Enter.
- **One free-text field**: the arguments are typed as on a command line, not as a form
  generated from the script's `param()` block. The scripts need nothing added to work here.
- **`.ps1` runs in `pwsh`**: `pwsh -NoProfile -File <script> <arguments>`, in the script's
  folder. `.bat` and `.cmd` run in `cmd /c`, also in their own folder.
- **Starting without arguments stays**: it remains available as a second command on the
  item; for `.ps1` it runs the script, not the editor.
- **Optional: earlier arguments**: the page lists the arguments used before for that script,
  so `start` and `stop` take one keystroke. Decided once the page works.
- **Prior art, rejected**:
  - *PaletteShell* (Command Palette gallery, MIT) turns `.ps1` scripts into commands with a
    form generated from `param()`. It reads one folder, top level only, needs
    `using module .\PaletteScriptAttributes.psm1` in each script for its attributes, and
    copies sample scripts, `AGENTS.md` and a reference into the folder it reads. Tried on
    2026-11-10 against `~\shortcuts`; it wrote into the repository.
  - *Bookmarks with placeholders* in Command Palette take inline values, but each one is
    saved by hand and does not come from the catalogue.
  - No extension was found that passes arguments to scripts from a catalogue of folders.

**Acceptance Criteria**:
- [ ] `ParametersPage` is confirmed in the SDK version the extension uses, or the SDK is
      updated to one that has it
- [ ] From the main search, `px-proxy stop` runs without typing the path, for the `.ps1` and
      for the `.bat`
- [ ] The script runs in its own folder, with the arguments as typed
- [ ] A `.ps1` started without arguments runs, and does not open in an editor
- [ ] A script can still be started without arguments
- [ ] All existing tests continue to pass
