# [CPS-005] The extension shows its own icon

**Status**: In Progress
**Priority**: Medium
**Component**: `src/CmdPal.Extension.Shortcuts/Assets/`, `src/CmdPal.Extension.Shortcuts/ShortcutsCommandsProvider.cs`

**Summary**:
As a user of Command Palette, I want the extension to have an icon in the list of installed
extensions, so that I recognise it at a glance.

**Description**:
Found in the UAT of CPS-002c: the list of installed extensions shows no icon for it. The
provider's `Icon` points to `Assets\StoreLogo.png`, and the package logos in `Assets/` are the
template's placeholders. Open: an icon of its own (PNG assets in the sizes the manifest names) or
a Segoe Fluent glyph for the provider icon, which needs no image files.

**Acceptance Criteria**:
- [ ] Command Palette's list of installed extensions shows an icon for the extension
- [ ] The package logos in `Assets/` are no longer the template's placeholders

**Scope Decisions**:
- **2026-11-13 - The logo of the shortcuts repo**: the icon is the logo of
  [xxthunder/shortcuts](https://github.com/xxthunder/shortcuts) (`docs/images/`, the hexagon
  with the four coloured quarters), not a Segoe Fluent glyph. Same author, both MIT.
- **2026-11-13 - A larger transparent source**: `shortcuts_logo_transparent.png` (221x256) is
  too small for the 300px tile and the 1240x600 splash, and `shortcuts_logo_orig.png` has the
  checkerboard painted in. The author exports a larger transparent PNG from
  `shortcuts_logo_title.xcf`; it is committed under `Assets/` as the one source of every logo.
- **2026-11-13 - Sizes from a script**: a script in `tools/` renders every logo the manifest
  names from that source, so a new logo is one file and one run.
- **2026-11-13 - Small target sizes too**: beyond the seven template files, `Square44x44Logo`
  also gets the `targetsize-16/24/32/48` variants, plated and `altform-unplated`, so small
  icons stay sharp.
- **2026-11-13 - Why no icon shows**: the provider's `Icon` already points to an existing
  `Assets\StoreLogo.png`; the work first finds out whether the path or the placeholder is the
  cause, and an extension test checks that the provider's icon names an asset that ships in
  the package.
