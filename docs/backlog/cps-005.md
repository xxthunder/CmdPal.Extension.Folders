# [CPS-005] ✅ DONE - The extension shows its own icon

**Status**: Done (2026-11-14)
**Priority**: Medium
**Component**: `src/CmdPal.Extension.Shortcuts/Assets/`, `src/CmdPal.Extension.Shortcuts/ShortcutsCommandsProvider.cs`

**Summary**:
As a user of Command Palette, I want the extension to have an icon in the list of installed
extensions, so that I recognise it at a glance.

**Description**:
Found in the UAT of CPS-002c: the list of installed extensions shows no icon for it. The
provider's `Icon` points to `Assets\StoreLogo.png`, and the package logos in `Assets/` are the
template's placeholders. Open: an icon of its own (PNG assets in the sizes the manifest names) or
a Segoe Fluent glyph for the provider icon, which needs no image files.

**Acceptance Criteria**:
- [x] Command Palette's list of installed extensions shows an icon for the extension
- [x] The package logos in `Assets/` are no longer the template's placeholders

**Scope Decisions**:
- **2026-11-13 - The logo of the shortcuts repo**: the icon is the logo of
  [xxthunder/shortcuts](https://github.com/xxthunder/shortcuts) (`docs/images/`, the hexagon
  with the four coloured quarters), not a Segoe Fluent glyph. Same author, both MIT.
- **2026-11-14 - A source keyed from the original**: `shortcuts_logo_transparent.png`
  (221x256) is too small for the 300px tile and the 1240x600 splash, and
  `shortcuts_logo_title.xcf` holds only flattened layers no larger than that. The source is
  `shortcuts_logo_orig.png` (1024x1024) with its painted-in checkerboard keyed out: everything
  outside the closed blue ring is background. The result, 704x704 with real alpha, is
  committed under `Assets/` as the one source of every logo; the author approved it.
- **2026-11-13 - Sizes from a script**: a script in `tools/` renders every logo the manifest
  names from that source, so a new logo is one file and one run.
- **2026-11-13 - Small target sizes too**: beyond the seven template files, `Square44x44Logo`
  also gets the `targetsize-16/24/32/48` variants, plated and `altform-unplated`, so small
  icons stay sharp.
- **2026-11-13 - Why no icon shows**: the provider's `Icon` already points to an existing
  `Assets\StoreLogo.png`; the work first finds out whether the path or the placeholder is the
  cause, and an extension test checks that the provider's icon names an asset that ships in
  the package.
- **2026-11-14 - The placeholder, not the path**: `IconHelpers.FromRelativePath` joins the
  path to `AppDomain.CurrentDomain.BaseDirectory`, the package's install folder, and
  `Assets\StoreLogo.png` was already packaged as content. The template's `StoreLogo.png` is
  a pale grey cross on a transparent ground, which reads as no icon. The UAT confirms it; if
  the list still shows no icon with the new logo, the path is the next suspect.
- **2026-11-14 - SkiaSharp renders the logos**: Visual Studio's manifest designer generates
  the visual assets from one source too, but only by hand, in Visual Studio on Windows, and
  the Linux gate cannot check its output; hence `tools/logos.cs`. It uses SkiaSharp (MIT).
  SixLabors.ImageSharp is out: 3.2.0 and 4.x print a missing-licence-key warning, and 3.1.12
  carries open security advisories. Skia has no Lanczos filter; linear filtering with
  mipmaps does the downscale.
