# [CPF-008] Requirements and traceability with sphinx-needs, sphinx-codelinks and ubCode

**Status**: Open
**Priority**: Medium
**Component**: `docs/`, `ubproject.toml`, `.github/workflows/ci.yml`, comments in `src/`

**Summary**:
As the author, I want the catalogue's rules written as requirements that link to their tests and to the code, so that what the extension promises and what proves it stay in one traceable place.

**Description**:
sphinx-needs (latest release `sphinx-ub-directives-v0.1.0`, 2026-11-04, checked 2026-11-08) for requirements in a Sphinx documentation; sphinx-codelinks (1.4.0, 2026-07-30) for markers in code comments — its documentation on `main` lists C# support (`FE_CSHARP`, tree-sitter); whether 1.4.0 already ships it is checked in CPF-008c; ubCode, the useblocks VS Code extension, through an `ubproject.toml`. The reference for the setup is useblocks/SPLed; shortcuts did the same for px-proxy (SC-073a–e), whose pattern is reused. Check the tools' changelogs at the start of each substory — they move weekly.

Substories:
- CPF-008a — A Sphinx documentation with sphinx-needs builds in CI
- CPF-008b — The catalogue's rules are requirements, linked to their tests
- CPF-008c — Code comments link to the requirements through sphinx-codelinks
- CPF-008d — A trace gate fails CI when a requirement has no test
- CPF-008e — ubCode shows and checks the requirements in VS Code

**Acceptance Criteria**:
- [ ] Every requirement links to at least one test, and the documentation shows the links
