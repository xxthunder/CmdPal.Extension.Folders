# [CPF-003] A command-line tool lists the catalogue for given patterns and extensions

**Status**: Open
**Priority**: Medium
**Component**: `tools/catalog.cs`, `scripts/gate`
**Related**: CPF-002a (the library it calls)

**Summary**:
As the author, I want to list from a terminal what the catalogue library finds for some
patterns and extensions, so that I can check it against my real folders — first for the
acceptance of CPF-002a, later to see why a file is missing from the main search.

**Description**:
A .NET 10 file-based app, `tools/catalog.cs`, refers to the library with
`#:project ../src/FoldersCatalog/FoldersCatalog.csproj` and calls `Catalog.Build`. It needs no
project file of its own and runs with `dotnet run tools/catalog.cs -- …`:

```
dotnet run tools/catalog.cs -- --ext ".url .lnk .cmd .bat .exe" "%USERPROFILE%\shortcuts\**" "%USERPROFILE%\shortcuts_private\**"
```

The arguments are the patterns; `--ext` takes the extensions, separated by spaces. Nothing is
built in — no default folders, no default extensions; those become the extension's settings
in CPF-002c. Output: one line per entry with name, folder and full path, then the number of
entries. Without patterns or without `--ext` it prints its usage and exits with 2.

**Scope Decisions**:
- **2026-11-07 — File-based app, not a project**: one file, no `.csproj`, no solution entry —
  the simplest thing that runs the library. A project comes only when the tool needs more
  than one file.
- **2026-11-07 — No defaults**: the tool takes everything as arguments, so the defaults have
  one place (CPF-002c).

**Acceptance Criteria**:
- [ ] `dotnet run tools/catalog.cs -- --ext "<exts>" <pattern>…` lists name, folder and full path of each entry and the number of entries
- [ ] Without patterns or without `--ext` it prints its usage and exits with 2
- [ ] `scripts/gate` also builds the tool, so a change to the library that breaks it turns the gate red
- [ ] The README says how to run it
