# [CPS-012] A script's earlier arguments are offered again

**Status**: In Progress
**Priority**: High
**Component**: `src/CmdPal.Extension.Shortcuts/ScriptArgumentsPage.cs`, `src/CmdPal.Extension.Shortcuts/ShortcutsCommandsProvider.cs`, `src/FoldersCatalog/`, `README.md`

**Summary**:
As a user of `~\shortcuts`, I want the arguments I gave a script before offered again, so
that `px-proxy stop` takes one keystroke after the first time, as it did in Keypirinha.

**Description**:
Since CPS-009, Ctrl+Enter on a `.ps1`, `.bat` or `.cmd` opens a parameters page with one
text field; its text becomes the arguments. Every run types them again. Keypirinha keeps
the arguments used before for each item and offers them when the item is locked in, so
`start` and `stop` for `px-proxy` are picked, not typed. It is the last thing Keypirinha
does that the extension does not.

This item is the follow-up named by the CPS-009 Scope Decision *Optional: earlier
arguments*.

The SDK's parameters page cannot show them: `StringParameterRun` holds plain text with no
suggestions, and the toolkit's only list for a parameter, `CommandParameterRun` with
`StaticParameterList`, is a second field that picks from fixed values (SDK 0.11.260520004
and PowerToys `main`, checked 2026-11-13). So the earlier arguments get a page of their own.

**Scope Decisions**:
- **Per script**: the earlier arguments belong to the script's full path; two scripts with
  the same name keep separate lists.
- **The history is the library's**: adding, ordering and capping the list live in
  `FoldersCatalog`, so they are tested on Linux; the extension only stores and shows it.
- **At most 10 per script** (the author, 2026-11-13): the oldest falls off when an eleventh
  is added.
- **Ctrl+Enter opens a list page, not the parameters page** (the author, Q&A, 2026-11-13):
  the page lists the script's earlier arguments, newest first; the search text filters
  them, and the first entry is always "Run with \"<search text>\"", so new arguments are
  typed in the same place. Enter runs the selected entry. It replaces CPS-009's
  `ScriptArgumentsPage`. Rejected: one context command per earlier argument (the menu
  grows with every argument), and a `StaticParameterList` picker as a second field on the
  parameters page (two inputs for one value).
- **Only a successful start is remembered** (the author, Q&A, 2026-11-13): arguments are
  saved when the script started; a failed start and empty arguments are not saved.
- **No "forget" command** (the author, Q&A, 2026-11-13): a mistyped entry drops out under
  the limit of 10.
- **A failed history write does not fail the start** (closed loop, 2026-11-13): when
  `history.json` cannot be written after a successful start, the script has already run, so
  the page ignores the write failure and closes as usual; the entry is lost, nothing else.
- **The search text is cleared after a start** (closed loop, 2026-11-13): the page instance
  stays with its item, so the next Ctrl+Enter starts from an empty search and lists the
  earlier arguments, as the old parameters page cleared its field.
- **`history.json` sits next to `settings.json`** (closed loop, 2026-11-13): in the
  extension's settings folder, a file of its own, not part of the settings.

**Acceptance Criteria**:
- [ ] Ctrl+Enter on a script opens a list page of its earlier arguments, whose first entry
      runs the script with the search text
- [ ] After `px-proxy stop` has run once, `stop` is offered for `px-proxy` and runs it
      without typing
- [ ] A failed start and empty arguments are not remembered
- [ ] The most recently used arguments come first; a repeated argument string appears once
- [ ] The list per script holds at most 10 entries
- [ ] The earlier arguments survive a restart of Command Palette
- [ ] New arguments can still be typed
- [ ] All existing tests continue to pass
