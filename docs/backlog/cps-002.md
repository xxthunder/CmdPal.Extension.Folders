# [CPS-002] Folders of your choice appear in the Command Palette main search

**Status**: In Progress
**Priority**: Medium
**Component**: `src/` (whole repository)
**Related**: shortcuts [SC-070](https://github.com/xxthunder/shortcuts/blob/develop/docs/backlog/sc-070.md) (trial of Command Palette as a Keypirinha successor)

**Summary**:
As a user of PowerToys Command Palette, I want to set up folders of my choice with a file-type
filter as a searchable catalogue, so that my scripts and links from `~\shortcuts` and
`~\shortcuts_private` appear in the main search and rise to the top by usage, as they do in
Keypirinha today.

**Description**:
The SC-070 trial shows that Command Palette covers every daily need except the author's own
scripts. The built-in *Installed apps* extension searches only the Start menu, the desktop and
`PATH`, and has no setting for other folders. It skips junctions in the Start menu on purpose
(`Win32Program.ProgramPaths`, `AttributesToSkip = … ReparsePoint`); entries from `PATH` appear
only on an exact name. Real `.lnk` files in the Start menu work, but arrive only after a
restart of Command Palette and would have to be regenerated on every change. The Everything
extension finds the files, but outside the usage ranking. The PowerToys requests are open
without a commitment: [#40379](https://github.com/microsoft/PowerToys/issues/40379) (custom
search path), [#40508](https://github.com/microsoft/PowerToys/issues/40508) (apps in a custom
folder).

The model is Keypirinha's `filescatalog.ini` in shortcuts: per profile `paths`
(`${env:USERPROFILE}\shortcuts\**`, `${env:USERPROFILE}\shortcuts_private\**`) and `filters`
(`.url .lnk .cmd .bat .exe`).

Design (as of 2026-11-07, SDK `Microsoft.CommandPalette.Extensions` 0.11, still preview):
- **Two projects.** A catalogue library (`net10.0`, no Windows dependency) turns folder
  patterns and extensions into a list of entries; the extension project
  (`net10.0-windows10.0.26100.0`, MSIX, from the template of Command Palette's
  *Create extension*) only maps entries onto commands. The library's tests run on any
  machine with Docker (`mcr.microsoft.com/dotnet/sdk:10.0`), the extension builds only on
  Windows.
- **Top-level commands.** The command provider returns one top-level command per catalogued
  file; top-level commands go through the built-in ranking by frequency and recency
  (`RecentCommandsManager`, since PowerToys 0.101), so the extension keeps no history of its
  own.
- **Settings.** Folders and extensions are settings of the extension (`JsonSettingsManager`),
  read at runtime — no rebuild to change them.
- **Live updates.** A file watcher on each folder rebuilds the catalogue and raises
  `ItemsChanged`, so a new script appears without a restart.
- **Published through the Microsoft Store** (CPS-010, 2026-11-13): the Store signs and updates
  the package, and the Extension Gallery points to it.

Substories:
- CPS-002a — The catalogue library lists files by folder pattern and extension
- CPS-002b — The extension lists the catalogue as top-level commands and starts a file
- CPS-002c — Folders and extensions are settings of the extension
- CPS-002d — A file added to a catalogued folder appears without a restart
- CPS-002e — The author installs a signed package from CI (superseded by CPS-010)

**Scope Decisions**:
- **Own repository**: shortcuts is PowerShell with Pester; a C# extension would bring a second
  toolchain into it. shortcuts only installs the extension.
- **Arguments for `.bat` later**: the first version starts the file; asking for arguments is a
  follow-up item.
- **Build on Windows**: MSIX and the Windows App SDK need Windows; the extension is built on
  the author's Windows machine or in CI on a Windows runner. The catalogue library is the part
  that is tested anywhere.

**Acceptance Criteria**:
- [ ] The extension is installed on the author's Windows machine and lists the files from `~\shortcuts\**` and `~\shortcuts_private\**` with the extensions `.url .lnk .cmd .bat .exe` in the main search
- [ ] Folders and extensions can be changed in the extension's settings without a new build
- [ ] A newly created script appears in the search without Command Palette restarting
- [ ] A file started before is on top at the next search
- [ ] CI builds the extension and runs its tests
