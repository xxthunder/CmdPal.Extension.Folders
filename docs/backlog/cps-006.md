# [CPS-006] Folders whose names start with a dot are left out unless named

**Status**: In Progress
**Priority**: Medium
**Component**: `src/FoldersCatalog/Catalog.cs`, `tests/FoldersCatalog.Tests/`

**Summary**:
As a user of the extension, I want tool folders like `.claude` and `.venv` left out of the
catalogue by default, so that the main search shows my scripts and not what tools keep beside
them.

**Description**:
Found in the UAT of CPS-002c: on Windows the catalogue lists files from `.claude` and `.venv`
below `~\shortcuts`. On Linux a leading dot means hidden and such folders were skipped already;
on Windows only the `Hidden` attribute does, which these folders do not carry.

Proposed rule, the same on every system: while walking below a pattern root, a folder whose name
starts with a dot is skipped. "Explicitly" means naming it: a pattern whose root is such a folder
(`%USERPROFILE%\shortcuts\.tools\**`) lists it as usual. Files are not affected — a file named
`.cmd` stays listed.

**Acceptance Criteria**:
- [ ] Below a pattern root, folders whose names start with a dot are skipped, on Windows and Linux alike, with tests
- [ ] A pattern whose root is a dot-folder lists it, with a test
