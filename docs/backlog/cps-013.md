# [CPS-013] One build harness for gate, CI and UAT

**Status**: Open
**Priority**: Medium
**Component**: `build.cs`, `uat.ps1`, `scripts/gate`, `.github/workflows/ci.yml`, `README.md`

**Summary**:
As the developer of this extension, I want one build script that the gate, CI and I all call,
and one script that deploys my checkout for a UAT, so that every command is written once and a
UAT starts with one line.

**Description**:
The list of build commands exists three times:
- `scripts/gate` builds `tools/catalog.cs` and runs the library tests in the .NET SDK container;
  CI's `test` job runs it.
- CI's `windows` job writes the same two steps out by hand, then adds the extension's tests and
  its Release build.
- README "Building and testing on Windows" repeats the `windows` job's four commands.

Running the library tests on both systems is right, because files behave differently there (dot-files,
the Hidden attribute). Copying the commands is not.

The UAT steps in every pull request repeat the same block as well: stop the extension, build it,
register its `AppxManifest.xml`, restart PowerToys.

**Scope Decisions**:
- **2026-11-14 - `build.cs`, a .NET file-based app**: it needs only the .NET SDK, which both
  systems need anyway, and follows `tools/catalog.cs` and `tools/logos.cs`, which the test
  runner already covers. Rejected: PowerShell (no `pwsh` on the Linux dev VM, Pester as a second
  test stack), a `.sh` plus `.ps1` pair (two copies again), Python or NUKE/Cake (a dependency
  for a handful of commands). On Windows it runs every step; elsewhere it runs the library steps
  and says it skipped the extension's.
- **2026-11-14 - `uat.ps1` deploys, separate from the build**: the gate and CI change nothing
  outside the repository, while a UAT registers a package and restarts PowerToys on the
  author's machine. `uat.ps1` is Windows-only PowerShell, which has `Add-AppxPackage` and
  `Stop-Process` as cmdlets. It builds through `build.cs` and repeats no build command.
- **2026-11-14 - Deploy what is checked out**: `uat.ps1` takes no pull request number. The
  author checks out the branch (`gh pr checkout <n>`) and runs it, so it also serves the
  everyday build-and-try loop.
- **2026-11-14 - `uat.ps1` without automated tests**: it is plumbing with side effects on the
  machine, which CI cannot run meaningfully. It stays free of logic; whatever needs a decision
  lives in `build.cs`, where it is tested.

**Acceptance Criteria**:
- [ ] `dotnet run build.cs -- check` runs every check of the repository: the library steps on
      every system, plus the extension's tests and Release build on Windows
- [ ] `scripts/gate` runs `build.cs` in the .NET SDK container and holds no build command of
      its own
- [ ] Both CI jobs call `build.cs`; `ci.yml` holds no build or test command of its own
- [ ] README's build section names `build.cs` and `uat.ps1` instead of the single commands
- [ ] `.\uat.ps1` on Windows stops the running extension, builds the checkout through
      `build.cs`, registers its `AppxManifest.xml` and restarts PowerToys
- [ ] README has a UAT section: `gh pr checkout <n>`, `.\uat.ps1`, then the item's own checks
